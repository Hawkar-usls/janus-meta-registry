## Reading rules

```text
ARCHIVED_OBJECT != CURRENT_CLAIM
HYPOTHESIS != RESULT
METAPHOR != PHYSICAL_EVIDENCE
CORRELATION != CAUSATION
HASH_OR_SIGNATURE != TRUTH_OF_CONTENT
PREREGISTRATION != POSITIVE_RESULT
INTERNAL_REPLICATION != INDEPENDENT_REPLICATION
CI_PASS != PEER_REVIEW
PROOF_IN_PATH != UNIVERSAL_PROOF_STATUS
```

Historical filenames may contain words such as `precognitive`, `tachyon`, `time traveler`, `God`, `Holy Clock`, `alchemy`, `P=NP`, or other project vocabulary. They remain unchanged for lineage and searchability. Their labels do not establish the literal proposition suggested by the name.

## Choose a review path

### A. Technical / skeptical review

Start with the [Technical Core Audit](docs/TECHNICAL_CORE_AUDIT_2026-08-09.md).

It highlights the registry material that is most technically useful:

- independent-future no-go/evidence hardening;
- AIFC and proof-carrying experimental evidence architecture;
- stacked proof-route repository audits;
- static archive forensics / safe software archaeology;
- adversarial protocol red-teaming;
- low-volume preregistered scheduler/revocation research;
- explicit unresolved-result tracking.

It also marks speculative, symbolic, theological, medical/high-stakes, and misleading-name families before a reviewer follows those links.

### B. Current research / engineering

For current external review, leave this archive and use:

- [Janus-Fundamentum](https://github.com/Hawkar-usls/Janus-Fundamentum) — scoped mathematics / proof-carrying work; A3 is frozen for external review.
- [AIFC](https://github.com/Hawkar-usls/AIFC) — auditable future-target protocol; independent Implementation B / external bench remain open.
- [janus-io-public](https://github.com/Hawkar-usls/janus-io-public) — controlled systems-measurement experiments.
- [janus-distributed-ai-swarm](https://github.com/Hawkar-usls/janus-distributed-ai-swarm) — embedded firmware / telemetry engineering.

Current portfolio authority: [`Hawkar-usls/Janus/portfolio-index.json`](https://github.com/Hawkar-usls/Janus/blob/main/portfolio-index.json).

### C. Creative technology

- [Janus_Genesis](https://github.com/Hawkar-usls/Janus_Genesis) — local-first interactive world / game.

Narrative, moral, mythological, and theological vocabulary in creative projects is separate from scientific evidence.

### D. Historical archive

Use [`data/INDEX.md`](data/INDEX.md) and `registry/` for older experiments, provenance objects, red-team records, personal/symbolic material, and corrections.

For each object ask:

- When was it created?
- What evidence class does it carry now?
- Is it a protocol, preregistration, result, receipt, hypothesis, or testimony?
- What exact source/provenance does it bind?
- Was it independently replicated or only internally replayed?
- Is there a later correction or dedicated repository that supersedes its authority?

### E. Safety / governance / medical-adjacent material

Treat these as design notes or research-planning artifacts unless they explicitly document a tested mechanism. They are not legal, medical, clinical, regulatory, or safety certification.

Any current medical/biological factual claim intended for external use should be checked against current primary literature rather than inherited from an archived registry note.

### F. Theology / care / symbolic material

Read this layer as **personal testimony, reflection, narrative, ethics, or declared belief**. It is not machine religious authority, prophecy, medical guidance, or empirical validation of technical work.
