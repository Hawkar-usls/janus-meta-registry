Evidence about the experiment — and evidence about the verifier.

AIFC (Auditable Independent Future Challenge) is a proof-carrying experimental architecture developed in the JANUS ecosystem. Its purpose is to make preregistration, target freshness, implementation identity, blinded review, verifier replay and final claim ceilings inspectable rather than collapsing them into a single “test passed” statement.

Current AIFC repositoryRegistry dossier

Preregister before reveal

Targets, thresholds, algorithms and verifier expectations are separated from later observations so a successful-looking outcome cannot silently rewrite what counted as success.

Bind exact implementation state

Code identity, package hashes, merge-tree state and replay receipts can be bound to the result so a later implementation is not substituted for the one that was actually tested.

Independent implementation matters

An implementation controlled by the claimant can demonstrate engineering consistency, but it does not by itself establish independent replication. A genuinely separate implementation or bench remains a stronger gate.

Preserve disagreement

Independent reviewers need not converge. If blinded reviewers disagree, the disagreement itself is a valid result and should remain in the evidence chain rather than being “resolved” by the claimant.

Core distinctions

PREREGISTRATION != POSITIVE_RESULT CI_PASS != PEER_REVIEW INTERNAL_REPLAY != INDEPENDENT_REPLICATION HASH_OR_SIGNATURE != TRUTH_OF_CONTENT VERIFIER_CONSENSUS != WORLD_TRUTH

Best external contribution

Build or audit a path that the claimant does not control: an independent implementation, external measurement bench, independent verifier, prior-art review or adversarial protocol analysis.

External contributor door

AIFC is evidence infrastructure. A well-designed protocol can improve the quality of inference; the protocol itself does not establish the extraordinary proposition it was built to test.
